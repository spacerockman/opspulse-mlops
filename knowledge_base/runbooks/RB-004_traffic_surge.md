# RB-004: 正常トラフィック急増時の判定・スケール手順書（誤報抑制ガイド）

- **対象サービス**: `order-service`
- **関連メトリクス**: `request_rate_rps`（通常の 2.5〜3.5 倍）, `cpu_percent` (80〜90%), `error_rate` (< 1%), `p95_latency_ms` (< 200ms)
- **重要度**: Info / Low（障害ではないがキャパシティ監視対象）

## 1. 障害との見分け方（False Positive 回避）
- セール・キャンペーン・メルマガ配信直後など、正当なアクセス急増により `request_rate_rps` と `cpu_percent` が同時に上昇する。
- **正常トラフィック急増の判断条件**：
  - `error_rate` が 1% 未満で安定していること
  - `p95_latency_ms` が SLO 上限（200ms）以内に収まっていること
  - `db_pool_utilization` が 80% 未満で推移していること
- 旧来の静的閾値（`CPU > 85%`）では誤報となっていたケースであり、ML 異常検知モデルでは **「正常（高負荷）」** と分類されるべきパターンである。

## 2. 推奨アクション
1. 即時の障害エスカレーションは不要（誤報としてクローズ）。
2. 高負荷状態が 15 分以上継続する場合、ECS オートスケーリング（Desired Count の増加）が正常動作しているか Grafana で確認する。
3. 業務トラフィック分布が恒常的に増加した場合、Evidently のドリフト監視レポートを確認し、新しいベースライン分布を含めたモデル再学習を計画する。
