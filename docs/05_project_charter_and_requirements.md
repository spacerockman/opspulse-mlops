## 1. 这是一个什么项目？（一句话讲透）

**OpsPulse MLOps** 是一个模拟日本 B2B SaaS 企业真实生产需求的 **「AI 运维异常检测 + 自动化模型生命周期管理（MLOps）+ AI 故障分析（LLMOps）」准生产级工程平台**。

它**不是**跑完就扔的 Jupyter Notebook 模型演示，而是一套**「从数据采集 → 特征契约 → 训练门禁 → AWS 云端推论 → 漂移监控 → 人工审批再训练 → 秒级回滚 → 日语 RAG 故障定界」**的完整企业级工程闭环。

## 2. 客户要什么？（Client Pain Points & Requirements）

假设我们的客户（或公司内部情シス／SRE 部门）正在运营一个核心日本 SaaS 订单微服务 `order-service`。客户提出以下 **4 个核心诉求**：

1. **「别再半夜因为大促正常高负载把我叫醒了，也别再漏掉内存泄漏！」（效果诉求）**
   - 现状（v0.1 静态阈值）：大促流量涨 3 倍、CPU 到 87% 就狂发误报（实测误报率 **36%**，大促场景误报率高达 **72%**）；而缓慢内存泄漏在 OOM 崩溃前 **0% 检出**。
   - 客户验收指标：误报率下降 `>= 50%`，内存泄漏早期召回率 `>= 85%`。
2. **「模型上线不能靠工程师手拷文件，出了事必须能 3 分钟内退回去！」（运维与风控诉求）**
   - 客户不敢用 AI 的最大原因不是模型不准，而是**一旦模型老化或新模型有 Bug，没人知道怎么查、怎么切回旧版**。
   - 客户验收指标：有自动质量门禁（不达标不许上线）、有数据漂移监控（Evidently）、再训练必须经人类审批（HITL）、坏模型回滚 `RTO < 3 分钟`。
3. **「告警响了之后，能不能顺便告诉我可能是哪篇运维手册、该敲哪条排查命令？」（提效诉求）**
   - 值班新人面对告警不知所措，MTTR 长。
   - 客户验收指标：AI Agent 自动结合指标与报错日志检索日语《運用手順書（Runbook）》，输出一次定界报告，且**不能瞎编不存在的命令（Runbook 引用命中率 >= 90%）**。
4. **「要能上真实 AWS 云跑，但个人/PoC 阶段预算有限，不能月烧几百美元！」（成本与交付诉求）**
   - 客户验收指标：Terraform 一键在 AWS 东京区拉起可访问服务、用完一键销毁（演练月成本 `< $20`），并交付完整日语《基本設計書》《運用手順書》与实测数据证据。

## 3. 我们要做什么？（Team Deliverables & Scope）

为满足客户上述全部诉求，团队 2 人在 **8 周（Sprint 0–4，共 24 张工单 `#0`–`#23`）** 内完成 **5 大工程模块** 的建设：

| 模块 | 我们要造什么 | 解决客户哪个诉求 | 负责主担 | 对应 Issues |
| :--- | :--- | :--- | :--- | :--- |
| **1. 数据与基础设施层** | Postgres + MinIO(S3) + MLflow 本地同构底座 + ETL Parquet 采集 + 线上预测与错误日志审计存储 | 解决数据溯源、Local-Cloud 一致性与漂移数据源问题 | **成员 A** | `#1, #2, #3, #12` |
| **2. ML 核心与共享契约** | `opspulse_core` 共享特征 + Pandera 契约 + LightGBM/IF 对比实验 + 质量门禁（`@challenger` → `@champion`）+ 一致性测试 | 干掉静态规则误报/漏报，彻底消除 Train-Serving Skew | **成员 B** | `#4, #5, #6, #9, #10, #11` |
| **3. 云端部署与 CI/CD** | 多阶段安全镜像 + GitHub Actions CI/CD + Terraform 省钱版 AWS ECS Fargate + Grafana 大盘 + 一键回滚 | 满足 P95 < 50ms、安全上线、3 分钟内紧急回滚与成本控制 | **成员 A** | `#7, #8, #13, #14, #15, #16, #21` |
| **4. 漂移监控与闭环演练** | Evidently 漂移报告 + GitHub Issue 告警 + 人工审批再训练（HITL）+ 坏模型回滚演练 + 7 天稳态压测 | 解决模型上线后退化失控问题，沉淀可验真的时间线证据 | **成员 B & 共同** | `#17, #18, #22` |
| **5. AI 故障分析（LLMOps）** | 日语 Runbook RAG Triage Agent + 告警联动触发 + Langfuse Cloud 全链路追踪与 15-20 条离线评估 | 缩短 SRE 故障一次定界 MTTR，用量化评估压制 LLM 幻觉 | **成员 B** | `#19, #20, #22` |
